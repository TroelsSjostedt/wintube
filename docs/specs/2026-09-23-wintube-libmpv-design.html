Design spec · Stage 10 · Approved 2026-09-23

WinTube libmpv Player

Replace Media Foundation with libmpv for video playback. YouTube's TV HLS manifests now use video-only TS variants plus packed-audio (ID3+AAC) renditions, which Media Foundation cannot play — every video silently fell back to 360p. libmpv plays these manifests natively, including VP9 up to 4K with Opus audio.

Base WinTube stages 1–9 Replaces MediaPlayerElement / AdaptiveMediaSource in PlayerPage Unchanged hover previews, InnerTube resolution ladder, sync, SponsorBlock data

0 · Stage-0 gate (build this first, prove it, then continue)

Nothing beyond stage 0 is built until the gate passes. A throwaway spike must prove, against a real VISIONOS hlsManifestUrl: audio+video playback, a variant above 360p, seeking, and rendering through the mpv render API into a XAML SwapChainPanel (OpenGL via ANGLE).
  • Pass fully → build the stage as specified below.
  • Playback passes, render-API embedding fails → fall back to a child HWND (--wid) hosting mpv's own video window; XAML overlays (comments, toast, transport bar) then render in an airspace-safe layer above it. The rest of the spec is unchanged — MpvPlayerHost hides the difference.
  • Playback itself fails → stop; the stage is re-evaluated from scratch.
  • Spike code lives in scratchpad and is thrown away; only the findings and the chosen embedding survive into the implementation.

1 · Binaries: pinned libmpv, download script

  • tools/get-libmpv.ps1 downloads a pinned libmpv-2.dll build (zhongfly/mpv-winbuild, x86_64) from its GitHub release, verifies a hard-coded SHA-256, and unpacks into libs/mpv/ (gitignored).
  • The app project copies libs/mpv/libmpv-2.dll to the output directory; a missing DLL fails the build with a message pointing at the script.
  • CI (release.yml and the test workflow if it builds the app) runs the same script before publish, so the DLL ships inside the Velopack package.
  • Upgrading mpv = bump one URL + one hash in the script.

2 · Binding: thin hand-rolled P/Invoke

  • New folder src/WinTube.App/Mpv/ (UI-bound, so it lives in the App project): MpvNative.cs with DllImports for the <20 functions used — mpv_create, mpv_initialize, mpv_command, mpv_set_property/get_property, mpv_observe_property, mpv_wait_event, mpv_terminate_destroy, and the mpv_render_context_* family.
  • No NuGet wrapper: the maintained ones lag mpv versions, and the API surface we need is tiny.
  • One event-loop thread per player instance pumps mpv_wait_event and marshals to the UI thread via DispatcherQueue. Property observation drives position/duration/pause/error state — no polling timers.

3 · MpvPlayerHost control

A single XAML control owns the SwapChainPanel, the ANGLE/EGL surface, the mpv handle and its render context, and exposes a small player interface. PlayerPage talks only to this interface; MediaPlayerElement and all AdaptiveMediaSource code is removed.

MemberMeaning
Load(url, startAt)Open a URL (filtered HLS manifest via data:/temp file, or direct MP4) and start at an offset — replaces today's resume-position logic.
IsPaused, TogglePause()Backed by mpv's pause property.
Position, Duration, PositionChangedFrom observed time-pos/duration; SponsorBlock skips and progress sync subscribe here.
SeekTo(seconds)seek … absolute.
Volume0–100, wired to PlayerSettingsStore exactly as today.
Speedmpv speed property, 0.25–2.
Opened, EndReached, ErroredFrom MPV_EVENT_FILE_LOADED / end-file reasons; drive loading ring, autoplay-next hooks and the error panel.
  • HTTP headers (stream user agent) pass via mpv's user-agent option; hardware decoding via hwdec=auto-safe.
  • Lifetime: created per PlayerPage navigation, destroyed on navigate-away (same discipline as today's player teardown; no leaked event threads).

4 · Custom transport bar

MediaTransportControls disappears with MediaPlayerElement, so PlayerPage gets its own overlay bar, bottom-anchored above the video:

  • Controls: play/pause · seekbar with elapsed/total time · volume (persisted) · speed picker 0.25–2× · fullscreen toggle.
  • Auto-hide: bar and cursor hide after ~3 s without pointer movement over the video; any movement or key brings them back. Bar stays while a flyout is open or the pointer is over it.
  • Click-to-pause on the video surface works as today (ancestor check so bar clicks don't fall through), and existing keyboard shortcuts (space, arrows, Esc) move over unchanged.
  • Fullscreen is ours (AppWindow FullScreenPresenter): the comments panel, skip toast and loading ring now also work in fullscreen — the parked "comments hidden in full-window mode" limitation disappears.

5 · Quality picker on mpv

  • mpv/FFmpeg's HLS demuxer plays one chosen variant; there is no continuous adaptive switching. The picker therefore works at the manifest level, reusing HlsVariantParser.
  • The master manifest is fetched once (as today); the menu lists one entry per height — VP9 heights (1440p/2160p) are now real choices since mpv decodes VP9/Opus.
  • Choosing a height builds a filtered manifest containing only that height's best variant plus all #EXT-X-MEDIA audio renditions, and reloads mpv at the current position. FilterToAvc generalizes into filter-to-selection.
  • Auto = the highest variant whose height does not exceed the current window/monitor resolution (manual choice can still force 4K). The label shows Auto · 1440p style, as today.
  • The preferred height remains session-static (preferredHeight), carried across videos.

6 · What does not change

AreaStatus

7 · Testing

  • Core tests: filter-to-selection manifest rewriting (chosen height kept, audio renditions kept, other variants dropped), Auto-height choice against a monitor resolution, parser regressions.
  • Manual gate per build: a known 4K video plays with audio at 2160p, seek works, SponsorBlock skips fire, progress resumes, fullscreen + comments coexist, quality switch keeps position.
  • P/Invoke and render plumbing are exercised by the app itself, not unit tests — the stage-0 spike is their proving ground.

8 · Out of scope

  • Continuous adaptive bitrate switching, subtitles/captions, audio-track selection, HDR passthrough, casting, picture-in-picture.
  • Replacing the preview pipeline or Shorts playback behavior beyond what MpvPlayerHost gives for free.
