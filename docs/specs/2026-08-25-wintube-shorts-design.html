WinTube Shorts

Shorts stop being filtered out: they get a row of their own with portrait tiles, and appear nowhere else — the tvOS behavior, replacing v1's drop-everything scope cut.

Playback The ordinary player — no vertical reel, as tvOS deliberately chose Base WinTube stages 1–4

1 · Feed rules (ported from FeedService.swift / Models.swift)

  • A Shorts row is kept, not dropped. The existing classification stands (reel shelf, SHORTS header glyph, or all-Short cells); an untitled Shorts row is titled "Shorts". Its items are all stamped IsShort = true — the row vouches for cells that didn't label themselves.
  • Stray Shorts are moved, not lost. Shorts lifted out of ordinary shelves are collected in document order and appended (deduped by id) to the response's Shorts row — or become one synthesized "Shorts" row at the end when the response has none. The no-shelves fallback gets the same treatment.
  • Row paging decides by row (FeedSection.Admitting(items)): a continuation reply is a bare cell list with nothing naming its shelf, so the row applies its own rule — a Shorts row stamps everything it pages in as Shorts; every other row drops the Shorts YouTube mixes in. FeedService.LoadMoreItemsAsync therefore stops filtering and returns raw items.
  • History folding ignores Shorts rows: a Shorts row is never a fold target and never folded away, and the history feed's retitle lands on the first non-Shorts row.
  • Search keeps its Shorts filter — Shorts appear only in the Home row.

2 · The tile (from the tvOS README's Shorts section)

AspectDecision
ShapePortrait 9:16, 150 × 267 px, 8 px corners — the format is the point, so nothing competes with the artwork.
ChromeNo title, no stats, no duration badge (a Short has no running time to show). The only overlay is the channel's avatar, 24 px circle bottom-right, when the cell carried one.
HoverA light 2 px edge around the tile — the video-card's caption treatment has no panel to light up here.
Row header"Shorts" with the row's own visual mark, so the format change reads as intentional.
ClickPlayerRequest into the ordinary player. SponsorBlock, progress recording and link copying work unchanged.

3 · Testing

  • Unit: the two v1 tests pinning drop-behavior are rewritten to pin keep-behavior (reel shelf → Shorts row; strays merged/synthesized, deduped, order kept); Admitting both directions; history folding skipping a Shorts row; search still filtering.
  • Manual (the user): Home shows a Shorts row with portrait tiles; a tile plays in the normal player; no portrait tiles inside ordinary rows.

4 · Out of scope

A vertical swipe-through reel player, Shorts in search results, autoplaying tile previews, and a dedicated Shorts page.
