Design spec · Stage 8 · Approved 2026-09-05

WinTube Comments

A Comments button in the player opens a translucent panel along the right edge — over the video, which keeps playing — with the top comments and one level of replies. Read-only, as on tvOS: no likes, no posting.

tvOS arbiters Player/CommentService.swift · Player/CommentsOverlayView.swift Base WinTube stages 1–7

1 · Core (port of CommentService.swift)

PieceDecision
ClientKind.WebNew identity in Clients.cs: name WEB, version 2.20260726.00.00, nameId 1, Chrome-on-Mac UA and referer https://www.youtube.com — the exact values from AppConfig.swift. Unauthenticated: comment calls send no Bearer.
Two-step fetchTopLevelAsync(videoId): /next {"videoId"} only locates the comments — the continuation token on the watch page's itemSectionRenderer with sectionIdentifier == "comment-item-section". No such section → a typed "comments unavailable" failure (comments are off for the video). The token then feeds the shared page fetch.
PageAsync(continuation)One parser for every page shape: comment bodies are commentEntityPayload entities keyed by commentId in frameworkUpdates; ordering and reply tokens come from the renderer list (commentThreadRenderer wrappers on top-level pages — each holding at most one replies continuationCommand; bare commentViewModels in order on reply pages). A page's own next-page token is the trailing continuationItemRenderer of the response's continuation-items list — never the tokens nested inside threads.
ModelsCommentItem(Id, Author, AvatarUrl, Text, PublishedTime, LikeCount, ReplyCount, RepliesToken) — author is the "@handle", timestamps and counts are InnerTube's pre-formatted strings shown verbatim, LikeCount falls back to "0", RepliesToken null when the comment has no replies. CommentPage(Comments, Continuation) with null continuation when exhausted.
Text fidelityEmoji arrive literally and are shown; formatting markup arrives raw and is shown verbatim — the tvOS prototype compromise, kept.

2 · The panel (port of CommentsOverlayView.swift)

AspectDecision
EntryA "Comments" button in the player's title bar beside Copy link. Toggles the panel; Esc closes it too.
Shape400 px column pinned to the player's right edge, full height under the title bar, dark translucent background — dark enough to read white text over any frame, light enough that the picture shows through. The video keeps playing and its transport controls keep working.
RowAvatar (32 px circle), "@handle · 2 years ago" muted line, the comment text (wrapping), and a muted "👍 1.2K · 14 replies" line. Rows with replies are clickable.
LevelsTwo, as YouTube's threads are flat: the top-level list, and one comment's replies with that comment pinned above them and a back button. Opening replies replaces the list; back returns to the top-level list at the same scroll position.
PagingA "Load more" row at the bottom while a continuation exists — top-level pages and "show more replies" pages alike.
LifetimeLoaded on first open per video; closing keeps the loaded list for reopening. Navigating away from the player (or to a new video) discards everything.

3 · Errors and edges

  • Comments off: the panel shows one quiet line — "Comments aren't available for this video." No retry.
  • Network failure: an error line with a Retry button, inside the panel. Playback is never touched by any comment failure.
  • Empty page: a video with a comment section but zero comments shows the panel with "No comments yet."

4 · Testing

  • Core: parser tests against synthetic /next responses — the two-step token discovery, unavailable (no section), both page shapes (threads vs bare view models), reply tokens present/absent, like-count fallback, trailing-vs-nested continuation tokens, empty page.
  • The WEB client's request shape (no Bearer, correct headers) pinned by a test.
  • UI verified visually — panel over playing video, drill-down and back, load more, Esc.

5 · Deliberately out

  • Posting, liking, sorting toggles, channel-owner badges, hearts — none of it is in tvOS.
  • Rendering comment markup/links; timestamps in comments are not clickable.
