WinTube Distribution

Friends install one Setup.exe from GitHub Releases and get updates automatically. Public repo, Velopack packaging, embedded client constants — nothing to configure and nothing to pre-install.

Repo github.com/TroelsSjostedt/wintube (public, created by this stage) Base WinTube stages 1–8

1 · GitHub repo

  • Create the public repo TroelsSjostedt/wintube via gh repo create, add it as origin, push master. Description from the README's first line; no issues/wiki ceremony.
  • Pushes remain user-initiated afterwards — except release tags, which are the release mechanism itself.

2 · Embedded client constants

  • Secrets.Load() falls back per-field to built-in defaults for the three YouTube-on-TV constants (InnerTube API key, OAuth client id, OAuth client secret) when secrets.json is absent or a field is empty. These are Google's own public TV-client app constants (in every TV firmware and in yt-dlp's source) — they identify the app, not a user; nothing personal is embedded.
  • The Appwrite fields stay file-only: sync is a personal opt-in and must not point friends at anyone's server by default.
  • secrets.json still overrides field-by-field. The README's setup section changes from "required" to "optional overrides".
  • Tests: absent file → defaults; partial file → mixed; full file → file wins.

3 · Velopack in the app

AspectDecision
BootstrapNuGet package Velopack; VelopackApp.Build().Run() as the FIRST line of Main (handles the install/update/uninstall hook invocations Velopack makes).
Update checkOn every app start, in the background after the window is up: UpdateManager with GithubSource("https://github.com/TroelsSjostedt/wintube", null, false). Not installed via Velopack (a dev run) → the manager reports as much and the check silently does nothing.
FlowNew version → download silently → apply on next restart. One quiet toast in the shell: "Update ready — restart for vX.Y.Z" with a Restart button (ApplyUpdatesAndRestart). Ignoring it is fine; the update lands on whatever launch comes next (WaitExitThenApplyUpdates on the pending package at exit).
FailuresAll silent (logged to the existing debug log). An update check must never delay or break startup.

4 · CI release pipeline

  • .github/workflows/release.yml, triggered by pushing a tag matching v*. Steps: checkout → .NET 8 SDK → run Core tests → dotnet publish src/WinTube.App -c Release -p:Platform=x64 -r win-x64 --self-contained -p:WindowsAppSDKSelfContained=true → vpk pack with --packVersion from the tag → vpk upload github (creates the GitHub Release with Setup.exe, the full/delta packages and releases manifest; uses the workflow's own GITHUB_TOKEN).
  • Self-contained means friends need no .NET runtime and no Windows App SDK installed.
  • Releasing is: git tag v1.0.0; git push origin v1.0.0. vpk downloads previous releases first, so deltas chain automatically.

5 · The friends' experience

  1. Open the release page, download WinTubeApp-win-Setup.exe.
  2. SmartScreen warns (no paid code signing): "More info" → "Run anyway".
  3. Per-user install (no admin), Start-menu shortcut, app launches; sign in with the usual device code. wintube:// registers itself on first run as today.
  4. Updates arrive by themselves at later launches.
  • README gains an Install section saying exactly this, above the build-from-source section.

6 · Notes and edges

  • The dev copy and an installed copy share %LOCALAPPDATA%\WinTube (tokens, progress, settings) — deliberate and convenient on the dev machine.
  • Version stamping: the tag is the single source; the assembly picks it up via vpk, and no csproj version needs manual bumping.
  • Rollback story: friends can install any older Setup.exe from a previous release.
  • Out of scope: code signing, winget, ARM64, a "check for updates" menu item, crash reporting.

7 · Testing

  • Core: the Secrets fallback/override matrix.
  • Local smoke: vpk pack on this machine and a Setup.exe install/launch on this machine (shares the data dir — expected), verified by Claude.
  • End-to-end: tag v0.9.0 → CI produces the release → install from GitHub → then tag v0.9.1 and watch the installed copy self-update.
